# A2/A3 素材 → 成片 制作说明（2026-10-07）

## 一、素材实况（实测）

| 文件 | 时长 | 真实画面 | 帧率 | 来源 |
|---|---|---|---|---|
| `素材/A线/A1.mp4` | 79.4s | 540×960 | 29fps | 微信导出（旧，低清） |
| `素材/A线/A2_raw.mp4` | 121.2s | **1080×1920** | 24fps | 小米直录（第1讲 想开点） |
| `素材/A线/A3.mp4` | 96.4s | **1080×1920** | 24fps | 小米直录（第2讲 情绪四步） |

**★ 坑：ffprobe 报 A2/A3 是 1920×1080（横屏），实际是竖屏。**
原因：小米手机录的带 `rotation=90` 元数据。**ffmpeg 会自动应用旋转，直出即 1080×1920。**
所以：**不用裁切、不用补背景，直接可用。** 但如果用 PIL/OpenCV 直接读，会得到横的图，要手动旋转。

## 二、语速实测与调整

| 素材 | 原始语速 | 标准 | 加速 | 调整后 |
|---|---|---|---|---|
| A2 | 3.79 字/秒 | 4.5 | ×1.15 | 4.36 字/秒 |
| A3 | 2.42 字/秒 | 4.5 | ×1.25 | 3.03 字/秒 |

**不能用"剪停顿"提速** —— 实测 A2/A3 里 >0.8s 的停顿是 **0 处**（说话几乎连续）。
**只能用 `atempo` 变速（不变调，声音不尖）。**

**音画同步的坑**：音轨用 `atempo` 加速时，**画面必须同步加速**（`setpts=(PTS-STARTPTS)/SPEED`），
且截取时间点也要按倍数换算（`trim=start={t*SPEED}:end={t2*SPEED}`）。只加速音轨会导致声画错位。

## 三、转录（本地可用）

**faster-whisper small 模型本地已有**：`E:/AIApps/models/whisper`

```python
import os
os.environ["HF_HUB_OFFLINE"] = "1"
from faster_whisper import WhisperModel
m = WhisperModel("small", device="cpu", compute_type="int8",
                 download_root="E:/AIApps/models/whisper")
segs, info = m.transcribe("A2_raw.mp4", language="zh", beam_size=5, vad_filter=True)
```

**不设 `HF_HUB_OFFLINE=1` 会去连 HuggingFace 并超时失败**（本机不通外网 HF）。

## 七、踩过的坑

1. **ffprobe 的宽高可能是"含旋转元数据"的值** —— 别直接相信，用 ffmpeg 直出验证
2. **视觉模型判"文字有无重叠/排版是否正常"极不可靠**（本次连续误报：说卡片是"小红书水印"、说"排版不正常"）→ **必须看原图 + 像素实测**
3. **后台跑批量渲染容易被中断** → 分批跑（2张一批）更稳
4. 卡片主标题长文案要降字号 + 舞台内缩，否则主舞台距边框会 <80px
