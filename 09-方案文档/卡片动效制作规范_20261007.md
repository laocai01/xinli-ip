# 「老蔡说」卡片动效制作规范 v1.0

> 签发：老马（CEO）　2026-10-07
> 依据：董事长口径「卡片页要想办法动起来，但重点要给人看的内容不能乱，同样要让人看得到和看清」

---

## 零、最高优先级铁律（★ 高于本文其余所有条款）

> **「无论你怎么做，我们要给人看的东西一定要清晰且能看到明白。」**（董事长 2026-10-07）

**这条压倒一切。任何创新、区分、动效，与它冲突时无条件让步。**

| 指标 | 硬标准 | 怎么验 |
|---|---|---|
| **清晰** | 文字锐利、不变形、不模糊、无压缩糊边；**出图不做二次放大** | 原分辨率看，文字边缘不发虚 |
| **看得明白** | 一眼扫过就知道这屏在说什么；主次分明；**禁止太花/太挤/看不清** | 陌生人视角：3 秒内能否说出这屏主题 |
| **安全** | 不压线、不越界、不侵入抖音遮挡区（y<1620） | `check_card_margins.py` 实测通过 |
| **动而不乱** | 动的是气氛；文字任何时刻都定得住 | 逐帧看，无重叠/错位/乱飞 |

**判据一句话：如果为了"好看/有区别"而牺牲了清晰或易懂 —— 那就是做错了。**

---

## 一、核心原则（董事长口径）

> **「动的是气氛，不是内容。文字是定海神针 —— 一动就散。」**

| 允许动 | 禁止动 |
|---|---|
| ✅ 背景光晕**缓慢漂移**（周期 10s+） | ❌ **带颜色的重点文字（焦点色块）—— 绝对不动** |
| ✅ 元素**依次入场**（一次只动一个） | ❌ 文字**旋转/晃动/闪烁** |
| ✅ 焦点色块**入场后即定住**（入场那一刻可有一次出现动作，之后永不位移/缩放） | ❌ 多个元素同时乱动 |
| ✅ 入场完成后**整体极缓推近**（3%，2s+） | ❌ 入场后元素再移位 |

**判据：任何时刻，观众的眼睛都能"定"在文字上。看不清 = 失败。**

## 二、动画时间轴（定稿，A线/B线通用）

| 时间 | 元素 | 动作 | 缓动 |
|---|---|---|---|
| 0.00-0.35s | 品牌条（LOGO+老蔡说） | 淡入 + 上移 26px | easeOut |
| 0.20-0.50s | 分隔线 | 横向展开（scaleX 0→1） | easeOut |
| 0.35-0.70s | 引子 | 淡入 + 上移 30px | easeOut |
| 0.60-1.05s | 主钩子 | 淡入 + 缩放 0.955→1.0 | easeOut |
| **0.95-1.35s** | **焦点色块** | **缩放 0.55→1.0（"砸下"）** | **easeBack（回弹）** |
| 1.25-1.55s | 分隔点线 | 淡入 | easeOut |
| 1.40-1.80s | 辅助句 | 淡入 + 上移 24px | easeOut |
| 1.70-2.10s | 底部（分享句+签名） | 淡入 + 上移 22px | easeOut |
| 2.10s 起 | 整体 | 极缓推近 3%（持续） | 线性 |

**整段时长：3.2 秒**（可拉伸到 3-5 秒）

## 三、技术实现（已验证可用）

### 路线：程序化逐帧渲染（**不是 AI 重绘**）

⚠️ **绝对不能把卡片画面丢给 AI 图生视频模型** —— 模型会**重画整张画面**，文字会花、会错位。**卡片里全是文字，必须走程序化渲染。**

### 工具链

| 环节 | 工具 | 说明 |
|---|---|---|
| 卡片设计 | HTML + CSS | 文字清晰锐利，可精确控制 |
| 逐帧渲染 | **Chrome CDP**（DevTools Protocol） | 一次开页、连续截图 |
| 视频合成 | ffmpeg | H.264 / yuv420p / 1080×1920 / 30fps |

**脚本（已验证）**：
- `E:\心理咨询IP\07-形象设计\卡片v2\anim_render2.py` —— 生成带时间轴的 HTML（注入 `setT(t)` 函数）
- `E:\心理咨询IP\07-形象设计\卡片v2\anim_cdp.py` —— CDP 逐帧渲染 → mp4

### 性能数据（实测）

| 方式 | 96 帧耗时 |
|---|---|
| ❌ 逐帧启动 Chrome（每次 `--screenshot`） | **150 秒** |

## 四、踩过的坑（必须避开）

| # | 坑 | 正确做法 |
|---|---|---|
| 1 | **分层截图会改变布局** | 把每个元素单独隐藏后截图，flex 布局会重排 → 元素位置全错。**必须在一个页面里用 JS 改透明度/位移，不能分层截** |
| 2 | **CDP 截图尺寸变成 1062×1824** | 少了窗口边框。必须显式调 `Emulation.setDeviceMetricsOverride(width=1080, height=1920)` |
| 3 | **主标题字号拉满会压线** | 148 号字把边距吃到 48px。降一档到 132 号 + 内边距加到 112px，边距回到 96px+ |
| 4 | **B线字少但焦点色块宽** | B线降到 122 号 + 内边距 132px |
| 5 | 中文路径喂 ffmpeg 报 `Illegal byte sequence` | 先 `shutil.copy` 成纯 ASCII 名（如 `E:/tmp/x.mp4`）再处理 |

## 五、验收（不许用指标自证）

**必须人眼看画面**，抽帧拼接触表后逐格判读：

### ★ 焦点色块 `<em>` 的两条硬规则（实测踩坑）

| 规则 | 为什么 |
|---|---|
| **`<em>` 前后不能紧跟别的字** | 色块的 padding + box-shadow 会**压住紧邻的字**，观众看到的是残缺笔画（实测：「…同一件事**上**」的"上"被压掉大半个，看起来像个"E"，观众直接说"文字压文字了"） |
| **`<em>` 要么独立成行，要么在行尾** | 同上；色块是"注意力焦点"，周围必须留白 |

**自查方法**：把色块上下各 80px 的区域裁出来放大看，确认没有孤立残缺笔画。

| 检查项 | 判据 |
|---|---|
| 文字压线 | 用 `check_card_margins.py` 实测，边距 ≥ 80px |
| 元素错位/乱飞 | 逐帧看，任何时刻文字不得重叠 |
| 末帧完整性 | 品牌条/引子/主标题/色块/辅助句/底部 **六项齐全** |
| 底部安全区 | 内容底边 < 1620（避抖音 UI） |
| 尺寸帧率 | 1080×1920 / 30fps / yuv420p |
